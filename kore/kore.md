# kore/

kore. これ, "this one here" — ano addresses the world from over there; the editor is where you hold it in your hand. A TUI over the process and text boundary: kore spawns anoc as a child exactly as anoc spawns cbqn, and its data contract is the .reg format. It never includes ano.h, so it survives the Steel port untouched. One file, `kore.c`, C23, zero external deps — raw ANSI CSI rendering over termios raw mode, double-buffered into one write(2) per frame, SGR mouse reporting, SIGWINCH resize, no ncurses. Strings, UTF-8, collation, and the world arena come from `../common` (the anoptic strings module, compiled in directly). CJK, kana, and fullwidth codepoints occupy 2 cells. Each parsed world lives in one arena and dies with the load that replaces it.

Build: `make -C kore`. anoc discovery: `$ANOC` wins, else `../src/anoc` beside kore's own binary, else `src/anoc` under CWD, else `anoc` from PATH. Runs need `bqn` on PATH (the nix dev shell provides CBQN).

The palette is pastel ink on a forced dark canvas: every cell paints its own background (xterm-256 `234`) and default text is soft off-white (`252`), so the colors read identically on a light-themed terminal — nothing leans on the terminal's own fg/bg. Deriving the palette from the shell theme instead (OSC 10/11, the way nvim does) is TODO.md item 4.

## Entry points

- `kore <file.reg>` — the bare world, REPL-only: no rail, no code surface, the prompt focused.
- `kore <file.ano>` — the demo form: code, world, output, prompt.
- `kore` — the rail: every .ano under `demos/` (walked from CWD at startup), in natural collation order (DUCET via common — kana in gojuon, a stem sorts before its own `-nihongo` conjugate, and digit runs compare as numbers, so `2-` precedes `10-` the way every file browser has ordered since the 90s), scrollable, selectable.
- `kore --check <file.reg>…` — headless verification: load each world, render table and space to memory, one ok/FAIL line each, nonzero on any failure.
- `kore --edit <file.reg> <seg> <row> <col> <value>` — headless cell edit, the same splice the inline edit performs (guard and undo bypassed — point it at a copy; a path under demos/ is refused, the corpus is immutable headless too).

## The world loop: r, n, u

The demo form owns a **play scratch** — `.kore/play/<demo-tag>/<registry>.reg`, tagged per demo (stem plus an 8-hex hash of the demo's absolute path), holding the mutable world with its session log, base snapshot, and undo ring beside it. Two demos never share any of the three; a demo and its `-nihongo` twin, addressing the same registry through the same tag inputs, each get their own. The demo's code is corpus too: the first mutating act on it (`s`, `E`) copies the .ano into the same play directory, the buffer rides the copy from then on (the title says `play copy`), and reopening the demo resumes it — a relative `--! registry` in the copy still resolves against the demo's home under `demos/`. Nothing under `demos/` is ever a write target.

- `r` — load and reset: the pristine registry is copied over the scratch and loaded, step zero. The pre-reset scratch stages onto the ring first, so u steps back across a reset. In a bare world r reloads the file.
- `n` — next: one tick. The demo's program runs against the scratch (`.kore/next.ano`: the demo verbatim, its `--! registry` retargeted, its `--! expect` pins stripped; then `anoc --run --save`), the pre-state staged first. The pins witness the pristine run — against any later step they would fail the tick and hold the world still, so the tick program drops them; `anoc --run` on the demo itself is still the witness. n repeats: each press advances the world again — the game loop under a key.
- `u` — undo: n's exact inverse, and the inverse of every prompt statement and cell edit too. The ring is files under `.kore/undo/`, so it survives kore itself; reopening a demo whose scratch exists resumes the play world and its ring where they stood, and r is always the way back to pristine.
- `>reset` — the whole play tree back to the corpus: typed at the prompt (`>` opens it pre-filled with the command form) or Ctrl+Shift+R where the terminal reports it (kitty CSI-u, modifyOtherKeys), it asks first — y confirms, any other key cancels — then deletes every play copy, code and world alike, with their rings and the tick scratch. Every demo is the pristine corpus again; snapshots are deliberate and stay.

## The tick

Each prompt submission is one program against the current world: kore writes `.kore/repl.ano` — `--! registry <world>`, the session's defs, then the one statement — and runs `anoc --run --save <world>`. One gather, one barrier, one scatter, then the world file advances (staged, rename(2), atomic) and the panels redraw from the advanced file. On failure the compiler's error lands in the output surface and the world stands. Defs persist across submissions exactly as the session log replays them: every successful `def` joins the session (same name resubmitted replaces it) and is prepended to each later same-surface submission, so `def kin = #/ (moore' & Planted)` submitted once serves every later statement, and resubmitting `Plot , Planted = kin == 3 | Planted & kin == 2` steps the world tick by tick — with the space up, the glider walks (n does the same for the demo's own program). The session log (`session.ano` beside the world) records every successful statement over a `session-base.reg` snapshot of the world as it stood before the first one, so the log is a valid .ano program that genuinely replays; reopening a world rehydrates its defs from the log — the log is the session's memory. A tick or a reset that moves the world underneath the log appends a `-- n:` / `-- r:` seam line, marked not replayable. A Japanese statement takes the `ja ` prefix at the prompt; a session keeps one surface (`--! ja` is file-wide), and a statement on the other surface logs as a comment, marked not replayable. One anoc limit surfaces here: the `--! registry` directive is one word, so a world whose absolute path contains a space cannot be addressed by the REPL.

## The surfaces

- demos — the corpus as a rail; Enter or click-on-selected opens. Directories dim, `-nihongo` twins tint violet, and the ASCII twin sorts first.
- code — the loaded .ano, edited in place, vim-vocabulary: browse with hjkl/arrows plus `w`/`b` word motions, `gg`/`G` (counts work: `5j`, `3dd`, `12G`), `0`/`^`/`$`; `i`/`a`/`o` insert (ESC leaves), `x` delete char, `dd` delete line, `u` code-local undo (a snapshot stack — the world's ring is untouched), `/` search (base-letter matching: case- and accent-insensitive, matches highlight, `n`/`N` walk them, ESC clears), `s` save. The title carries a `line/total` indicator and the right border a scroll thumb. Saving is always explicit — `n` refuses to tick on unsaved changes rather than write the file under you — and never reaches the corpus: `s` on a demo under `demos/` redirects to the play copy, announced in the output surface. Directives hold their own hue, comments dim, `def` heads glow, numbers and operator glyphs tint, the hinge comma and `=>` glow.
- world — the registry's data whole: every column in world order, presence gaps dimmed to `·`, rel columns as row indexes with `/` the visible none, alias lines as their stored mask bits, srel fibers, lattice fields in their w×h shape below the table, kanji names at correct width, value hues by kind (sym lilac, rel salmon, bool teal, char warm). The title names the state — `(pristine)` before the first act, `(play · step N)` on the scratch, N the ring depth. The cell cursor reaches every value; Enter opens the inline edit (Enter commits, ESC cancels). A rel cell accepts `/` for none; a vec cell takes `x y`; an srel cell takes the whole fiber (numbers only); a char cell takes one printable ASCII byte and refuses a write the loader could not read back (a boundary space, a word-boundary `#`). Edits splice one word in the .reg text — comments and layout pass through untouched, never regenerated.
- space — `m` toggles table ⇄ space: the world as a glyph grid looked down at. char fields draw their exact glyphs, bool fields block-paint in a per-field color, num fields shade ░▒▓█ against their max (coordinate fields x/y skip — they would drown the picture), positioned entities (the pos role, else the literal `pos` vec column) stand on their cells as `@`. The cell cursor and mouse work on the map exactly as on the table; Enter edits the field that painted the cell.
- output — child stdout/stderr verbatim (`--! out` prints land here), prompt echoes and tick lines tinted by origin, failures in the error hue, and the one verdict line: pins held, which statement failed, or the save/undo status — green when the world advanced, red when it stands.
- the prompt — its own boxed panel above the status line, reachable from anywhere with `:` or `>`. A statement can span lines: `\⏎` (a trailing backslash before Enter), Shift+Enter (kitty CSI-u and xterm modifyOtherKeys encodings), or Alt+Enter all break a line, and Enter runs the whole body as one program (its def lines join the session individually, exactly as the log replays them). The box grows with its lines to a third of the screen, then scrolls to the cursor's line with a thumb on the border; the cursor's line scrolls horizontally under the cursor (an `…` marks the clipped head). ↑↓ walk lines inside a multi-line body and the session history past its edges; the wheel walks history; ESC leaves.
- the status line — the bottom row belongs to the key atlas alone, context-sensitive per focus, with the mode chip at the right edge.

## Keys and mouse

Global (outside text entry): `q` quit, Tab cycle focus, `:` or `>` the prompt, `m` table ⇄ space, `r` reset, `n` next, `u` undo, `w` snapshot, `E` the $EDITOR hop (opens the world under world focus, else the .ano; reloads on return), j/k or arrows scroll, PgUp/PgDn page. ESC steps out of any panel to the mode's home surface — the rail, the code, or the prompt. In code focus the vim keys win: `u` is code undo, `w` a word motion, `n` the next match while a search is set (clear it with ESC and `n` ticks the world again). Inside the prompt, an edit, or insert mode, keys are text; ESC leaves first. Mouse: click focuses and cursors, click a selected rail entry opens it, wheel scrolls the panel under the pointer (over the prompt it walks history), click the prompt to type, the wheel moves one item per notch, and dragging across world rows or space cells paints a selection whose predicate skeleton pre-fills the prompt — `index >= a & index <= b , ` over rows, `w h & x >= … & y <= … , ` over cells (registered x/y fields are sampled so either row/column convention lands right). Pointing at the world is the language's founding gesture; kore takes it literally.

## Mutation and the ring

In the demo form the first mutating act (r, n, a statement, or a cell edit) copies the current world into the demo's own `.kore/play/<tag>/` directory, says so in the output surface, and retargets the session there — the demo's own registry never mutates under kore. A bare `.reg` world mutates in place, unless it sits under a `demos/` tree, which always copies: the corpus is immutable. Every world advance first copies the pre-state to `.kore/undo/<key>-<seq>.reg`; `u` steps back. Scratch names carry `<key>` = the file's stem plus an 8-hex hash of its absolute path, so two worlds sharing a basename never share a ring. The ring is files, so it survives kore itself — reopening a world resumes the count. `w` writes `.kore/<key>-snap<seq>.reg`. All scratch lives under `.kore/` in the CWD; the working file is always committed truth (every write is staged → rename).
