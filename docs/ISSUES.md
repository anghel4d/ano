# Ano — issues

What is still open, after the conways and noita suites (demos/10-conways, demos/11-noita) and the native-noun witnesses (demos/9-nihongo s50-s55). Everything else those suites surfaced has been fixed, and the record lives where it landed: the emitter conformance fixes in src/GRAMMAR.md's contract lines and the demo READMEs, the shared rule barrier and the guard-complement clause beside §11 in ano-language.md, the anchored frame under the spec's Coordinate frames entry, the eval splice under Staging, and the dump-is-pre-state entry closed 2026-07-10 by the `--save` pipe-back (src/GRAMMAR.md's pipeline line; kore's REPL tick is its consumer). The suites changed very little language: the wand stress test needed no new grammar at all, and closing its gaps added two surface forms (`at` in the frame slot, `eval`) and one resolution rule (a key column standing in relation position).

- Identity across the barrier. A trigger payload records parent = the carrier's gather-time row while the same barrier despawns the carrier: extensional data outliving the intensional surface. n4-trigger pins it as data; where the intensional/extensional boundary sits is the spec's Identity entry, unresolved.
- Recurrences within a statement. The cast pointer between wand blocks is a carried recurrence. Across ticks it is already expressible: the game loop is the scan, so a cursor column advanced by a standing rule works today. The within-statement carry stays rejected, and the w-series takes the pointer as host-supplied data (w2's rot binding) pending that cursor.
- Quotation past the literal. eval splices a literal one-statement string at parse time, footprint visible to the static checks. A runtime-built string has an opaque footprint and waits on the interpreter. The analyzable middle (templates with holes, the koto nominalizer, rules writing rules) is unbuilt.
- Order-srel derivation. w3-b's binds fibers are listed by hand in the registry; deriving them mechanically from a declared ground order (the way moore follows from the lattice) is registry-side work not yet done.
- World-to-chunk frames. The anchored frame fills a frame's origin from the world, but the world-to-chunk (o, S) conversion itself has no surface: n6's impact binding carries coordinates the host already converted.
- Rule ticks are frame-homogeneous. All rules sharing a tick must select in one habitat; a mixed entity-and-lattice tick (steer the bolt and burn the cell in one barrier) is rejected today.
- Post-state meets the text format at its seams. Some BQN worlds have no .reg spelling, and `--save` refuses them rather than commit a file the loader rejects — nothing is written, the error names the column: an empty sym (a spawned row's default — write the sym in the spawning statement), a glyph run that is empty or carries boundary whitespace or a word-boundary `#` (despawn can produce all three), a non-finite value (`∞` from a division), a column made part-pair by a partial pair write. Two lossier seams commit anyway: stored masks — `alias` entries, `bind … mask` — are row-length data the barrier never restructures (the BQN world neither filters them on despawn nor pads on spawn), so the save reconciles them to the new n by zero-pad on growth and positional truncate on shrink purely so the dump reloads — after a despawn the kept bits can sit on the wrong rows; and a vec column despawned to n 0 re-spells as `num`, its pair-ness carried by no value; and a `-0` saves as `0` (CBQN's •Repr drops the sign inside AnoSaveNum) while `--dump` preserves it, so load∘save is identity up to the sign of zero. Whether stored masks should track structure is the same intensional/extensional boundary as the Identity entry above.
- Entity binds are positional. `bind <name> entity <k>` mirror-reads emit `((↕anoN)=k)` and `k⊑col` — a positional read, stale after a despawn, the same latent class the functional hop had before 02's fix, and the fix is the same shape: resolve k through the key space. No corpus demo despawns past an entity bind. Not in 02's mandate; recorded so the class has one open entry.
- Gamma value-folds read fibers positionally in non-iota-id worlds before any despawn. The 02 fix translates fiber keys to live rows for keyed srels and for any world after rows shift; the remaining case — an entity srel in a world whose id column is not the row iota, before any structural commit — still gathers positionally, because fixing it would change emitted bytes for id-carrying worlds (the strict byte-identity rule). No corpus demo exercises it.
- Scan length meets selection width at runtime, not plan time. A scan whose scope selects a different row count than the assignment's selection crashes in AnoScat ("expected ⟨3⟩, got ⟨0⟩") instead of failing with a compile diagnostic — `Nord , Gold = +\ Damage @ none` always had the hole, and named scans plus `&\ |\` now reach it too. A plan-time width check is the fix shape.
- Guards are temp-free by convention. emitEffect's world-mode guard probe evaluates the RHS once to harvest its guard, then discards the staging buffer — the guard string survives, any temps staged under it do not. So a guard must stay a self-contained expression, and three sites now lean on that (relGuard, the keyed hop, the chain hop); the keyed hop pays for it with a duplicated key⊐rel, once in the gather clamp and once in the guard. The structural fix is guards carrying staged deps that survive the probe discard. Until then the convention is load-bearing, not stylistic: a guard built on a staged temp emits an assignment RHS referencing a variable whose defining line the probe threw away — the observed miscompile. The same hole now gates a todo-10 feature: a keyed srel's identityless γ fold in effect position miscompiles trace-on and trace-off alike, so the FIBER trace is unreachable there until the probe keeps its deps.
- reg_load counts srel fibers leniently. A 3-row world with 3 `|` separators loads as 4 fibers and dies only at runtime with a BQN shape error; a load-side fiber-count check against n would turn it into a line diagnostic.
- Two reports stand unreproduced. The 2/12 multi-effect that "wasn't firing off in some strange case": retracted as not replicable, nothing order-dependent found in the emit path — the report stands unreproduced. And whatever the tick trace doesn't explain of s10a's terminal-buffer complaint ("strange writes according to the terminal buffer"; the s10a exponential itself is exactly what `--trace`'s per-statement rows-before/after line makes obvious). The repro channel both wait on is kore's: the session log plus the play registry IS the bug report (kore/kore.md, The repro channel) — either report closes the day a session log replays it.
- The clock is the install runs. In the real engine `def … => …` only installs. Rules run on the clock: every installed rule, one shared barrier per tick, tick after tick. anoc has no clock, so it pretends the clock beats once at the end of each unbroken run of def lines, and each beat fires every rule installed so far. Installs persist: a rule installed early fires again at a later beat, as the engine would have it (n5-c pins this, spread ringing twice while consume joins a tick late). What stays approximate is the tick count: the clock beats only where install runs sit, so a file cannot let two ticks pass without installing something new, and no rule fires again after the file's last beat.
