## The two rulings

Registry-as-API (2026-07-07, the author's notebook diagram — transcribed in INTERACTIVE.md). Complexity belongs registry-side, never as language quirks. The registry is an API with three layers: the C API, authoritative — the end state is registration happening in the host's C source at compile time via standard structs, anoptic_engine style, `anostr_t`-like checked value types; the storage files, `.reg` today and `.anoreg` in the diagram's naming, persisting regardless as data at rest — saves, arcade user data; and the in-memory representation, a spectrum from virtual (anoc's arena tables) to direct ECS (the same structs over anoptic_engine's live store). ano.h's `Registry`/`RegEntry` are the proto-ABI and `reg_load` is the text frontend's constructor, nothing more. The text frontend's directive family is `as`, `ja`, `role`; its commit loop is read in → binary tables in-memory → write out to a staged file → mv commit.

Case (2026-07-08). One rule, no exceptions: names are always case-insensitive; values — strings, char glyph runs, `:Sym` symbols — are always case-sensitive. Simpler = Better. The first-letter-only fold in `reg_find` (src/registry.c:368) and `reg_role` (src/registry.c:387) is wrong in both directions, too narrow to be the rule and too magical to be no rule; it widens to a full ASCII fold.

Measured against all 100 registries before this plan was written: 111 of 229 demos lean on name folding, so the fold is the rule and not a bug; zero registries declare names that collide under the full fold; zero declare exact duplicates; zero entry names fold to a lexer-reserved word; seven registries under the demos' STABLE seal — the standing demos-are-immutable rule, lifted under Docs below — declare identity aliases (`ja x x`, `ja y y`) whose source words equal entry names, so alias-vs-entry shadowing is load-bearing. Every change below is corpus-free and the one carve-out is measured.

Work items, in order:

1. One comparator. Add a `names_eq` helper to registry.c: ASCII letters compare case-folded, every other byte exact, so kanji and all UTF-8 names are untouched by construction. Use it everywhere a name resolves — the entry loop and both hops of the alias loop in `reg_find` (src/registry.c:369-380), both loops of `reg_role` (src/registry.c:388-397), and the loader's own directive lookups (`find_exact`, src/registry.c:124, serving pres/default/inv/role targets) — replacing the first-letter tolower comparisons and the exact strcmps alike. 2. Load-time strictness, scoped within name kinds. 3. `as` name-alias lines. `as <word> <name>`: a pure name alias with the ja hop's exact semantics — one hop, no transitivity, outranked by real entries, source word `wfree`-checked, both hops compared with `names_eq` like every other name. A third arity `as <word> <col> <value>` declares a derived tag — the word names the equality mask over the live column; specified in DATAMODEL.md, lands with this item.

4. One resolver for roles. With the comparator unified, the reg_role divergence (PATCHES.md verification report, finding #1) narrows to one question: does `reg_role`'s literal-name fallback consult the alias table (one rule everywhere — entries, then aliases) or stay entry-table-only? The fallback calls `reg_find` — one resolution path in the compiler, entries then aliases — and the declared `role` line remains the explicit override whenever plumbing must be pinned, which answers the action-at-a-distance worry. State the behavior in one line in compiler.md and GRAMMAR.md.

5. `reg_dump`. The write-out half of the commit loop: `--dump <path>` serializes the post-state world back to .reg text — n, lattice, columns with post-state values, rels, srels, binds, fns, roles, aliases, everything `reg_load` reads, round-trippable. Verification gains an axis — load → dump → load → dump must fixpoint, the second dump byte-identical to the first, and a dumped world must pass the same pins as the in-memory one. This is the save file: the world is a column store, so a save is a registry dump.
