# src/

The source code of the ano lang's infrastructure:
- Compiler code.
- Parser / Interpreter.
- Integration infrastructure.

## anoc

`anoc` is the C oracle: an Ano-to-BQN transpiler with CBQN as the execution engine. Its emitter implements one gather-effect-scatter barrier per statement. Steel is the Rust reference. `GRAMMAR.md` records the C oracle's surface contract; the language spec remains authoritative.

- `ano.h` — the one contract: token columns, AST, registry, directives, module APIs; header-only arena, string buffer, and intern pool (one canonical copy per spelling, FNV-1a open addressing).
- `lex.c` — tokenizer, ASCII surface plus the Japanese skin (particle table, kanji numerals, ex40's TGT-drop and postfix re-root normalization). Both skins are registry-blind: identifiers admit any codepoint >= U+0080 outside a small blacklist and carry their surface spelling to resolution at emit; the `^alias`/`:Sym` sigil names follow the same policy (`:山賊`); the closed grammar (`lex_reserved`) outranks all nouns. The stream is struct-of-arrays — kind/name/num/line columns grown together — and token text is interned, no per-token buffers. Source is validated as strict UTF-8 once at the ano_lex boundary (overlongs, encoded surrogates, out-of-range rejected); unknown characters report by codepoint.
- `parse.c` — Pratt parser over the spec appendix's 14 precedence levels.
- `registry.c` — registry loader; the `.reg` file format is specified at `reg_load` in ano.h. A registry stands in for the host: columns, presence, relationships (functional, set-valued, inverse reads), aliases, bindings, and callables carrying their own BQN — the eventual host ECS replaces exactly this file. Entry names are any legal identifier, UTF-8 included; lexer-reserved words are rejected at load under the case fold, and `reg_find` resolves entry names first, then `as`/`ja` aliases, every compare through the one comparator (names fold, values never). A `role <name> <col>` line points a system-column role (keys id parent proto pos) at a native column, so `reg_role` routes the spawn machinery by declaration, else for id/keys by the first declared unique column (declared beats guess: a declared unique outranks a merely magic-named `id`), else by reg_find on the literal name. The typed layer (the s10 bundle): `unique <col> …` declares injectivity — pairwise-distinct checked at load, no `default`, no `pres`, effects never assign it; `rel <key> <name> …` / `srel <key> <name> …` key a relationship to a unique column (two names before numeric data, LL(1)), and the inv of a keyed rel is keyed automatically with fibers in key space; `def <name> <col>=<v> …` registers a proto (archetype), the format's one row-oriented named-value construct; `reap seal|host` records the `~` reclamation policy, storage only. `reg_dump` writes the world back out — every new kind round-trips — staged file, rename(2) commit.
- `emit.c` — AST to BQN codegen against the registry; carries the semantic conventions (sym columns as strings, char columns as glyph strings pinned exactly, pair columns, id-space fiber membership, fold identities and row-drop, Tier-1 field inscription vs entity spawn). Spawn's key mint, parent, proto, and `at`-position all route through `reg_role`, so a native world's roles land on kanji-named columns; a `def` proto fills spawns by the ruled three-layer lookup (proto value, registered default, type zero) and stamps its noun into the proto-role sym column, and a unique column always mints fresh. Hop integrity: a keyed rel resolves by `key⊐rel` with one found-guard (not-found is dangling is dead — ¯1 and a despawned target fail alike, left-join-null); an unkeyed rel keeps the positional gather until a despawn commits, after which it resolves the same way through `anoIdx`, the fixture row iota materialized once and carried through structural commits — armed by a whole-program pre-scan (scanNeedIdx), so a program with no despawn-then-hop emits today's bytes exactly. Keyed srel images take membership through their key column; gamma fibers translate keys to live rows (dead members drop) when keyed or shifted. Registry names that are not BQN-legal identifiers mangle to stable `jp<i>` variables, the human spelling kept in a fixture comment, so a natively Japanese world emits legal BQN. The `--trace` hooks ride the guards that already exist: the keyed hop and the fiber translate stage a dead-mask report beside the found-guard they observe, the identityless gamma folds name the rows their empty-fiber guard drops, and commitStmt prints the row-count delta from the same staged expressions the commit scattered by — every hook flag-gated, so tracing off emits today's bytes and tracing on costs only output.
- `fs.c` — path values and file reading, ported and miniaturized from the anoptic-engine filesystem module: AnoPath (a checked value type — truncation is a detectable len 0, never a silently clamped open target), exe-dir discovery, dirname, checked join, lexical ./.. normalization, and the one fortified reader (rejects directories, detects short reads, preserves errno) both main.c and registry.c go through.
- `rt.bqn` — the runtime prelude (Ano-prefixed helpers: dense rank, scatter-under-mask, fiber image, inverse fibers, clamp shift).
- `main.c` — driver: `anoc [--tokens] [--emit] [--run] [--save] [--label] [--dump <path>] [--rt <path>] [--registry <path-or-name>] file.ano`; `--!` directives name the registry and pin expectations, compiled into BQN assertions, so `--run`'s exit code is the differential-test verdict. `--label` tags every query's value on stdout over a 0x1D channel (`q<stmt>@<line>` then the shown value) so a host can label results by source statement; pins still assert beside the display. `--trace` is the debug observability channel over 0x1F, one control byte below 0x1D: one `RELATION <column> <origin> -> <sink> IS DEAD !` line per dead link a hop's found-guard drops, one `FIBER <column> <origin> IS EMPTY !` line per empty-fiber row failure, one `s<N>: <before> rows -> <after> (spawn <Proto>: +k, kill: -j)` line per structural statement — observability, never semantics: post-state is byte-identical with the flag on and off. Both flags are off by default — the emit is byte-identical without them.
- world fixtures — a `<name>.reg` in `demos/registries/` reproduces each demo's initial world exactly; the twin's `--! registry ../registries/<name>.reg` loads it. A bare `--! registry <name>` still resolves beside the `.ano`, so a fixture may sit next to its twin instead.
- `check-ano.sh` — runs every demos/**/*.ano through `anoc --run`, ok/FAIL per file (mirrors demos/check.sh), then pins every `X-nihongo.ano` byte-identical to its twin under `--emit`, ok-emit/FAIL-emit per pair, then runs `check-refusals.sh`.
- `check-refusals.sh` — the negative battery over `refusals/`. It pins load and save rejection for non-finite values, overflow, invalid effects, and typed registry violations. The registry's value domain is exactly the finite doubles; load ∘ save is the identity on it.

Build and test (inside the dev shell for CBQN): `make -C src && ./src/check-ano.sh`, or `make -C src test`.

Known gaps, deliberate for now: spawned rows take registry defaults, not source-row copies; an effect verb cannot share its target column's name (reg lookup is kind-blind); `--! expect` targets registry columns only, so def-derived columns pin indirectly; numeric expectations compare within 1e-9 (float pins come from sibling BQN evaluations). The generation notes under the demo twins record each omission per file.
